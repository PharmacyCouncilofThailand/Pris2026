## สิ่งที่ใช้ร่วมกัน

- Login PRIS เช่นเดียวกับหน้าบัตร เปิดจาก LINE OA ได้ รองรับ TH/EN
- สุ่มจริงที่ API หลังตรวจ Main Session check-in วันนี้และสิทธิ์หนึ่งครั้งต่อ user/event/day
- ในภาพมี 6 ช่องเพื่อเป็นตัวอย่าง ระบบจริงเพิ่ม/ลดจากหลังบ้านได้
- ช่องแก้วหมดเป็นสีเทาและอยู่ตำแหน่งเดิม มีโอกาส 0%; เมื่อเติมกลับมาจะเข้าสุ่มอีกครั้ง
- ช่องเสียใจด้วยไม่จำกัดจำนวนและไม่มี QR รับรางวัล แต่ใช้สิทธิ์ของวันนั้น
- ทุกช่องที่ยังใช้ได้มีโอกาสเท่ากัน เมื่อของจริงหมดทั้งหมดหยุดเล่น ไม่ปล่อยให้สุ่มเสียใจด้วยอย่างเดียว
- ประวัติและผลเดิมเปิดดูได้ แม้ปิดหน้า เปลี่ยนอุปกรณ์ หรือหมดเวลาเล่นแล้ว

## หน้าจอถัดจากการหมุน

| สถานะ                  | การแสดงผล/ปุ่มหลัก                                                   |
| ---------------------- | -------------------------------------------------------------------- |
| ยังไม่ check-in วันนี้ | อธิบายเงื่อนไขพร้อมทางไปหน้าบัตร ปิดปุ่มหมุน                         |
| นอกเวลา Main Session   | แสดงช่วงเวลาจาก server ปิดปุ่มหมุน                                   |
| เล่นได้                | สถานะวันนี้ วงล้อ กติกาโอกาส และปุ่มหมุนหนึ่งปุ่ม                    |
| ข้อมูลวงล้อเปลี่ยน     | โหลดชุดใหม่ ให้ผู้ใช้ตรวจและกดอีกครั้ง ไม่หักสิทธิ์                  |
| ไม่ทราบผลเพราะเน็ตขาด  | ตรวจผลคำขอเดิม ป้องกันการเริ่มหมุนซ้ำ                                |
| ได้รางวัล              | รูป/ชื่อของ เวลา และปุ่มเปิดหลักฐานรับของ                            |
| เสียใจด้วย             | บอกว่าไม่ได้รางวัลครั้งนี้ ใช้สิทธิ์วันนี้แล้ว และมีประวัติ ไม่มี QR |
| ของจริงหมด             | “ของรางวัลหมดแล้ว” พร้อม “กรุณารอเติมสต็อก” ไม่หักสิทธิ์             |
| พักกิจกรรม             | แจ้งพัก แต่ยังเปิดประวัติและหลักฐานได้                               |
| หลักฐานรับของ          | ชื่อผู้รับ รูป/ชื่อของ เวลาได้รับ QR/รหัส สถานะ จุดรับและกำหนดปิดรับ |
| รับแล้ว                | แสดงสถานะและข้อมูลการรับจาก server ไม่มีการสร้างสิทธิ์รับใหม่        |
| พ้นกำหนดรับ            | แสดงกำหนดเดิมและช่องทางติดต่อผู้จัด ไม่คืนสต็อกอัตโนมัติ             |

## ขอบเขตของภาพร่าง

ภาพสร้างด้วย built-in image_gen เป็นภาพตัวอย่างสำหรับเลือก composition ไม่ใช่ screenshot ของระบบที่ทำเสร็จแล้ว รูปปากกา เสื้อ แก้ว และข้อมูลทั้งหมดเป็นตัวอย่าง ไม่ใช่รายการของรางวัลจริง

ใช้ Header/โลโก้จริงของ PRIS จากโค้ดเดิมในการพัฒนา ไม่ใช้โลโก้ที่ AI วาดในภาพ และไม่เปลี่ยน Header ของหน้าอื่นจากภาพร่างนี้ สัญลักษณ์ของขวัญที่ภาพวาดในช่องเสียใจด้วยจะเปลี่ยนเป็นเครื่องหมายกลาง ๆ เพื่อไม่สื่อว่าได้รับของ ข้อความช่อง/ผลต้องระบุว่าไม่ได้รางวัลอย่างชัดเจน ไม่รับประกันว่าเล่นได้วันพรุ่งนี้หลังจบงาน

ตำแหน่งกราฟิกเป็นแนวทาง; ข้อความ วงล้อ ปุ่ม และ QR จริงต้องสร้างเป็น UI ที่เข้าถึงได้ ไม่วางภาพ raster แทนระบบ ใช้ขนาดตัวอักษร/contrast ที่อ่านได้ และปรับปุ่มส้มตามผลตรวจ contrast ห้ามย่อข้อความจนเล็กเพื่อให้ครบจอ ภาพแนวตั้งแสดงเนื้อหาที่เลื่อนได้ ไม่บังคับทุกอย่างให้อยู่ในหน้าจอเดียว

หากเลือก C แถบปุ่มต้องไม่ทับเนื้อหา คีย์บอร์ด หรือ safe area; หากเลือก B บัตรไม่ถูกบังคับอัตราส่วน 9:16 จนวงล้อ/ข้อความล้น กรอบบัตรเป็นรูปแบบการจัดวาง ไม่ใช่ข้อจำกัดความสูง

ภาพพร้อม prompt และ approval sidecar อยู่ใน `.impeccable/mocks/lucky-wheel-{a,b,c}.{png,json}` และ `.prompt.txt` แบบ B ระบุ `approved: true` พร้อมวันที่และข้อความยืนยันจากผู้ใช้ ส่วน A/C เก็บไว้เป็นตัวเลือกที่ไม่ได้รับเลือก

## การยืนยันขั้นนี้

ผู้ใช้เลือก “แบบ B” เมื่อ 3 ตุลาคม 2026 ให้ดำเนินการตามกรอบบัตร รอยปรุ วงล้อ และปุ่มใต้รอยปรุของ B โดยคงข้อยกเว้นด้านโลโก้ ข้อมูลสมมติ และ accessibility ตามเอกสารนี้ การอนุมัติภาพไม่ใช่หลักฐานว่ากฎธุรกิจถูกทดสอบแล้ว
