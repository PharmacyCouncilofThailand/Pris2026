# P08 — Thai recipient and server quote review

The authenticated checkout starts with the existing account's name and phone only; address fields remain blank. A different recipient is allowed. The form collects full name, Thai phone, one address line, subdistrict, district, province and a five-digit postal code, with optional company and delivery note. Country is Thailand; there is no guessed province/postcode lookup, guest email, recipient email, tax checkbox or address book. Limits and phone normalization follow the actual backend schema, including the 200-character recipient name and preservation of leading postal zeroes.

All fields have associated labels/autocomplete, linked errors and first-invalid focus. The form uses text inputs for postal codes and tel input mode for phones. Optional company/note blanks become null. Editing these values changes component memory only, not the account or browser storage; reload requires address re-entry. The account email is displayed for order notifications without creating another email field.

R08 supplies the reviewed recipient, item/options/Bundle snapshots, quantities, prices, shipping and total. A real stale-cart 409 reads current cart/store data and requests a fresh quote when still eligible; the changed details are explicitly presented for review. Price changes without a cart revision change are also detected against displayed server values and announced. Closure/invalid carts prevent a new quote/order, network errors remain retryable, and no R09 request is made by this task. Null production/shipping text does not produce sections. Preorder and combined domestic delivery with 50-baht shipping are stated without an invented schedule.
